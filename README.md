## 🌟 Overview

**The GuestInn** is a full-stack, mobile-first hotel management PWA built specifically for small and mid-size Indian hotels. It replaces manual register-based check-ins with a smart AI pipeline — from ID scanning and rate negotiation to real-time room tracking and guest self-service.

The system has two distinct sides:

| Side | URL | Who Uses It |
|---|---|---|
| **Hotel Dashboard** | `/` | Hotel owner / manager |
| **Public Booking Page** | `/booking/[hotelId]` | Walk-in & online guests |

Guests can book directly from the hotel's unique link, negotiate rates with an AI concierge, get checked in via ID scan, and then use a persistent **In-Room Digital Companion** for Wi-Fi, food orders, housekeeping, and more — all without installing anything.

## ✨ Key Features

### 🤖 AI-Powered Core
- **Sandy AI Concierge** — Hinglish chatbot (Llama 3.3 70B) embedded in every guest booking page; answers hotel-specific questions autonomously (Wi-Fi password, menu, checkout time, policies)
- **AI ID Scanner** — Llama 4 Scout Vision OCR for Aadhaar, PAN, Passport, Driving License; auto-fills the entire GRC form from camera capture
- **AI Rate Negotiator** — Guests can negotiate room rates in natural Hinglish; the system enforces a `min_floor_price` per hotel and returns a cryptographic `RLT-XXXX` rate-lock token when approved
- **AI Revenue Briefing** — Dashboard greets manager with a personalized daily briefing (occupancy, revenue, pending check-ins) generated by Groq

### 🏨 Hotel Dashboard (Owner Panel)
- Real-time room grid with live occupancy status (Vacant / Reserved / Occupied / Cleaning)
- One-tap guest check-out with automatic room status reset
- Today's bookings, weekly revenue chart (Recharts AreaChart)
- Guest database with search and filter
- Reports view with revenue analytics
- Settings panel — configure rates, Wi-Fi password, menu, amenities, push notification subscription

### 📱 Public Guest Booking Page (`/booking/[hotelId]`)
- Premium dark luxury UI with gold accents, matching brand identity
- Visual Room Allocator grid — live room status pulled from Supabase + localStorage
- Side-by-side form layout (Name/Mobile, Check-in/Check-out, Gender/DOB)
- AI ID Scanner with camera modal, front/back capture, progress indicator
- Negotiated rate lock displayed inline before confirmation
- **Persistent Guest Session** — active booking stored in `localStorage` as `air_active_booking_${hotelId}`; returning guests skip the booking form and land directly in the In-Room Companion
- SEO: dynamic JSON-LD Hotel schema, FAQ accordion (AEO-optimized), Reputation & Trust section

### 🛎️ In-Room Digital Companion
Automatically opens after confirmed booking. Four tabs:

| Tab | Feature |
|---|---|
| **Sandy Chat** | Full AI concierge with booking context injected; rate negotiation, food queries, service requests |
| **Food** | Digital menu display (text or URL); order instructions via Sandy |
| **Room Service** | One-tap request grid (cleaning, water, towel, AC issue, wake-up call, DNC, bill) — fires to manager dashboard + logs to `service_requests` table |
| **Call Desk** | Direct call + WhatsApp deep link to reception; check-in/check-out time display |

### 🔔 Notification System
- **Push Notifications** (Web Push / VAPID) — manager receives instant alerts for new bookings and room service requests
- **WhatsApp Alerts** — `wa.me` deep links for new booking notifications to owner phone
- **Email Alerts** — Resend API for booking confirmations and guest welcome kit emails

### 🏪 Multi-Hotel Marketplace
- `/` landing page with hotel search by city
- Marketplace listing cards with ratings, amenities, pricing
- Each hotel gets a unique SEO-optimized booking URL
- `NegotiatorOrb` — floating AI widget on marketplace for cross-hotel rate queries

### ⚡ Data & Sync Layer
- **Dual-write hybrid** (`lib/db.js`) — writes to `localStorage` first (instant UI), then syncs to Supabase in background
- **BroadcastChannel** — real-time cross-tab sync; dashboard refreshes instantly when a booking is made from another tab or device
- **localStorage sentinel** — `air_sync_${hotelId}` timestamp fallback for browsers that block BroadcastChannel

```

│                    VERCEL EDGE (bom1)                   │
│                                                         │
│  ┌─────────────┐    ┌──────────────┐    ┌───────────┐  │
│  │  Next.js 14 │    │  API Routes  │    │  PWA/SW   │  │
│  │  App Router │    │  (Edge Fn)   │    │  next-pwa │  │
│  └──────┬──────┘    └──────┬───────┘    └───────────┘  │
│         │                  │                            │
│  ┌──────▼──────────────────▼───────┐                   │
│  │         lib/db.js               │                   │
│  │  Dual-Write: localStorage ←→    │                   │
│  │  Supabase (background sync)     │                   │
│  │  BroadcastChannel (cross-tab)   │                   │
│  └──────┬──────────────────┬───────┘                   │
└─────────┼──────────────────┼───────────────────────────┘
          │                  │
  ┌───────▼──────┐   ┌───────▼──────────────────────────┐
  │  SUPABASE    │   │  GROQ API                        │
  │  PostgreSQL  │   │  • llama-3.3-70b (Sandy chat)    │
  │  + RLS       │   │  • llama-3.3-70b (negotiate)     │
  │  hotels      │   │  • llama-4-scout (ID OCR vision) │
  │  bookings    │   │  • llama-3.3-70b (briefing)      │
  │  rooms       │   └──────────────────────────────────┘
  │  service_req │
  └──────────────┘
```

**Request flow for a guest booking:**
1. Guest opens `/booking/[hotelId]` → hotel config fetched from Supabase (falls back to localStorage demo data)
2. Guest selects room from live grid → fills form → optionally scans ID via Groq Vision
3. Guest submits → `saveBooking()` calls `createBooking()` in `lib/db.js`
4. `lib/db.js` writes localStorage instantly → fires BroadcastChannel → syncs to Supabase async
5. `/api/push` fires Web Push to manager's subscribed browser
6. `lib/alerts.js` sends WhatsApp + email notification
7. Guest lands in In-Room Companion; session persisted in `localStorage`

## 🗄️ Database Schema

Four core tables in Supabase (all with Row Level Security enabled):

### `hotels`
Stores every registered hotel's full configuration.

```sql
id                TEXT PRIMARY KEY        -- e.g. "cherry-bhopal"
name              TEXT                    -- "Hotel Cherry"
location          TEXT                    -- "Peer Gate, Bhopal, MP"
total_rooms       INTEGER DEFAULT 20
owner_pin         TEXT                    -- 4-6 digit PIN (hashed in prod)
manager_pin       TEXT
owner_phone       TEXT                    -- Indian mobile: 91XXXXXXXXXX
standard_rate     INTEGER DEFAULT 1200    -- ₹/night
deluxe_rate       INTEGER DEFAULT 2000
suite_rate        INTEGER DEFAULT 3800
min_floor_price   INTEGER DEFAULT 800     -- AI negotiator hard floor
wifi_password     TEXT
menu_text         TEXT                    -- pipe-separated: "Dal ₹120 | Roti ₹15"
menu_url          TEXT
reception_phone   TEXT
enable_wifi       BOOLEAN DEFAULT TRUE
enable_food_ordering BOOLEAN DEFAULT TRUE
enable_housekeeping  BOOLEAN DEFAULT TRUE
amenities         TEXT[]                  -- ["Free Wi-Fi","AC","Parking"]
avg_rating        NUMERIC(3,2)
is_active         BOOLEAN DEFAULT TRUE
```

### `bookings`
Every guest booking — direct, marketplace, or walk-in.

```sql
id               TEXT PRIMARY KEY         -- "BK1A2B3C4D"
hotel_id         TEXT REFERENCES hotels
guest_name, guest_phone, address, gender, dob
id_type          TEXT                     -- Aadhaar | PAN | Passport | DL | Voter ID
id_number        TEXT                     -- stored as "[Aadhaar Redacted]" in GRC logs
room_id, room_type, room_number
check_in_date, check_out_date, nights
rate_per_night, total_amount
payment_mode     TEXT                     -- Cash | UPI | Card | Online
status           TEXT                     -- active | checked_out | cancelled
negotiated       BOOLEAN DEFAULT FALSE
negotiated_from  NUMERIC                  -- original rate before AI negotiation
rate_locked      BOOLEAN DEFAULT TRUE
source           TEXT                     -- direct | marketplace | walkin
```

### `rooms`
Live room state — synced bidirectionally with localStorage.

```sql
id               TEXT PRIMARY KEY         -- "{hotelId}_R001"
hotel_id         TEXT REFERENCES hotels
number           INTEGER
floor            INTEGER
type             TEXT                     -- standard | deluxe | suite
status           TEXT                     -- vacant | occupied | reserved | cleaning
current_booking_id TEXT
guest_name       TEXT
base_rate        INTEGER
```

### `service_requests`
Real-time guest requests from the In-Room Companion.

```sql
id               UUID DEFAULT gen_random_uuid()
hotel_id         TEXT REFERENCES hotels
booking_id       TEXT
room_number      TEXT
guest_name       TEXT
action_id        TEXT                     -- "clean" | "water" | "towel" | "ac" | etc.
title            TEXT
message          TEXT
status           TEXT                     -- pending | in_progress | done
created_at       TIMESTAMPTZ
```

> **Setup:** Run `supabase_schema.sql` in your Supabase SQL Editor. Safe to re-run — all statements use `IF NOT EXISTS` / `IF NOT EXISTS` guards.

## 📡 API Reference

All routes are in `app/api/` and use `export const dynamic = "force-dynamic"`.

### `POST /api/groq`

Unified Groq AI endpoint. Dispatches on `type` field.

| `type` | Model | Description |
|---|---|---|
| `chat` | llama-3.3-70b | Sandy concierge chat with full hotel context injection |
| `id_scan` | llama-4-scout-17b (vision) | OCR — extracts name, DOB, address, ID number from image |
| `negotiate` | llama-3.3-70b | Rate negotiation — validates against `min_floor_price`, returns `RLT-XXXX` token |
| `ai_briefing` | llama-3.3-70b | Dashboard morning briefing for manager |
| `ai_insight` | llama-3.3-70b | Revenue tip based on today's stats |

**Chat request body:**
```json
{
  "type": "chat",
  "hotelId": "cherry-bhopal",
  "hotelConfig": { "name": "Hotel Cherry", "wifiPassword": "cherry@2024", ... },
  "messages": [{ "role": "user", "content": "Wi-fi ka password kya hai?" }]
}
```

**Negotiate request body:**
```json
{
  "type": "negotiate",
  "hotelId": "cherry-bhopal",
  "requestedRate": 900,
  "roomType": "standard",
  "hotelConfig": { "standardRate": 1200, "minFloorPrice": 800 }
}
```

**Negotiate response:**
```json
{
  "success": true,
  "approved": true,
  "requestedRate": 900,
  "finalRate": 900,
  "floorPrice": 800,
  "discountPct": 25,
  "rateLockToken": "RLT-CHER-M2X9KZ",
  "message": "✅ Rate lock ho gaya! ₹900/night confirm! 🎉"
}
```

## 🔍 Feature Deep-Dives

### Dual-Write Data Layer (`lib/db.js`)

The data layer uses a **localStorage-first, Supabase-async** pattern to ensure the UI is always instant while data eventually syncs to the cloud:

```
Guest books → localStorage write (0ms, instant) 
           → BroadcastChannel fires (all open tabs refresh)
           → Supabase REST POST (background, ~200ms)
           → Push notification fires
```

This prevents the common race condition where Supabase latency would cause the dashboard to show stale data after a booking.

---

### AI Rate Negotiator

When a guest types something like *"₹900 mein milega?"* in Sandy's chat:

1. `detectNegotiationIntent()` matches the regex pattern
2. Frontend calls `POST /api/groq` with `type: "negotiate"`
3. Server fetches `min_floor_price` from Supabase for that hotel
4. Approval logic: `requestedRate >= floorPrice` AND `discount <= 30%`
5. If approved: generates `RLT-XXXX` rate-lock token, AI writes a friendly Hinglish approval message
6. Token is stored in component state and embedded in the final booking record (`rate_locked: true, negotiated: true`)

---

### Persistent Guest Session

After a successful booking, the booking metadata is written to:
```js
localStorage.setItem(`air_active_booking_${hotelId}`, JSON.stringify(bookingResult))
```

On next page load, the page checks for this key. If a valid, non-checked-out session exists, the booking form is hidden and the **In-Room Companion** is surfaced directly — so returning guests never see an empty room grid.

Session is cleared when the guest taps **"Check-out ho gaye? Session clear karo"**.

---

### SEO & AEO Architecture

Each hotel's booking page at `/booking/[hotelId]` includes:

- **JSON-LD Hotel schema** dynamically populated with hotel name, location, price range, and aggregate rating
- **FAQ accordion** with 5 high-intent local queries answered in conversational Hinglish (optimized for AI Answer Engine scraping by ChatGPT, Perplexity, Claude)
- **Reputation section** with Google-style rating breakdown and guest review cards
- Static blog pages in `/public/blogs/` for long-tail SEO targeting
